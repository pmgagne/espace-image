# Calendar Bug Fixes - February 17, 2026

## Summary

Fixed two critical bugs in the calendar event caching system discovered after the icalevents migration:

1. **Recurring events losing occurrences** - Only the last occurrence was cached
2. **All-day events displaying on wrong date** - Timezone conversion shifted events to previous day

## What Was Broken

### Bug 1: Missing Recurring Event Occurrences

**Example:** A biweekly event scheduled for both Friday Feb 13 and Friday Feb 27:

- ✅ icalevents correctly returns: 2 occurrences (Feb 13 & Feb 27)
- ❌ Database cache contained: Only 1 occurrence (Feb 27)
- **Why:** Deduplication logic used only the event UID as a key, so multiple occurrences with the same UID were treated as duplicates and only the "latest" was kept

### Bug 2: All-Day Events Showing Wrong Date

**Example:** Event scheduled for Friday, February 13:

- ✅ Calendar says: Friday, Feb 13, 2026
- ❌ Browser displayed: Thursday, Feb 12, 2026
- **Why:** All-day events stored at midnight UTC (00:00) shifted 5 hours earlier when converted to America/Toronto (UTC-5), resulting in 19:00 on Feb 12

## What Was Fixed

### Fix 1: Composite UIDs for Recurring Events

**Before:**

```
Event UID: abc-123
Database: Only stores last occurrence
```

**After:**

```
Event UID: abc-123
Database stores:
  - abc-123#2026-02-13T00:00:00+00:00 (first occurrence)
  - abc-123#2026-02-27T00:00:00+00:00 (second occurrence)
```

Each occurrence gets a unique composite UID that includes the datetime, allowing all occurrences to coexist in the database.

### Fix 2: Noon UTC Storage for All-Day Events

**Before:**

```
Stored: 2026-02-13 00:00:00 UTC
Toronto: 2026-02-12 19:00:00 EST
Display: Thursday, Feb 12 ❌
```

**After:**

```
Stored: 2026-02-13 12:00:00 UTC
Toronto: 2026-02-13 07:00:00 EST
Display: Friday, Feb 13 ✅
```

All-day events now stored at noon UTC instead of midnight, preventing date shifts in negative UTC offset timezones.

d5fcdcc3-...-0257#2026-02-27T00:00:00+00:00 | 2026-02-27 12:00:00 | Congé 1 vendredi sur 2

✅ Both occurrences present
✅ Stored at noon UTC (12:00) for all-day events

### Timezone Conversion

```python
utc_noon = datetime(2026, 2, 13, 12, 0, 0, tzinfo=ZoneInfo('UTC'))
toronto = utc_noon.astimezone(ZoneInfo('America/Toronto'))
# 2026-02-13 07:00:00-05:00 → Friday, Feb 13 ✅
```
